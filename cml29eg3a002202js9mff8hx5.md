## 1\. Why version control exists

When someone starts learning software development, writing code feels like the main thing. But very soon, one thing becomes clear. Code does not stay fixed. It keeps changing again and again.

A small change here, another change there, and suddenly the file looks very different. At that point, a question naturally comes. What if something breaks? What if the older version was actually better?

This is where version control starts making sense. Version control exists because code has a history. And managing that history manually is very difficult. Version control keeps record of changes so that code does not get lost and older versions are not forgotten.

It is not about writing more code. It is about **controlling changes** in code.

## 2\. The pendrive analogy in software development

Before learning about version control, it was surprising to see how developers used to share code earlier.

They used pendrives, emails, and shared folders. One person writes code, copies the project into a pendrive, and gives it to another person. That person makes changes and sends it back.

Folders were named things like `final`, `final_v2`, `latest`, `final_latest`, and sometimes even more confusing names. At that time, this was the only way.

But when thinking deeply, this method has many problems. If two people work on the same file, one person’s work can easily overwrite the other’s changes. There is no clear idea of what changed and when.

This pendrive style works only for very small work. As soon as more people are involved, everything becomes confusing.

## 3\. Problems faced before version control systems

One big problem was **overwriting code**. Someone saves a file, and another person’s changes are gone forever.

Another problem was **losing versions**. If a mistake is made, there is no simple way to go back. Old files are scattered everywhere with unclear names.

There was also **no history**. Nobody knew who changed what or why. When bugs appeared, finding the cause was very hard.

As projects became bigger and teams became larger, these problems became serious. This is why version control became necessary. It solved these issues by keeping proper history, avoiding overwrites, and making collaboration possible.

This is how version control slowly became an important part of modern software development.
